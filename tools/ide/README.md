## Server modules (node, CommonJS)
`ictx` = `{ gameDir, mods:[names], folder, vfs?, maxChars?, exe?, game? }` (folder = the mod root; all optional: without a game, do what the text alone allows). `exe` (`as64`|`mowas_2`|`goh`) or `game` (a lib/games id) names the game (intel/game.js `gameOf`): every vfs build, keylint call and entity index of the Editor gets that exe, and each cache key carries it (`|mowas_2`, `|goh`; none for as64, so AS64 keys are unchanged). Nothing named = as before (the vfs default: as64 when as64.exe is there); a GoH folder (call_to_arms.exe) with nothing named reads the GoH tables (vocab.goh.json, gohweb rows). `vfs` = the layered file view the GUI already built (a lazy getter put there by the routes; null when there is none): use it, do not build a second one. `maxChars` = check size limit (default 1 MB; the CLI passes Infinity).
`doc` = `{ key, text, file? }` (key may be null for a file the engine never reads; text = editor text with `\n` line ends).

### tools/ide/intel/check.js (part check)
- `check(doc, ictx) -> [finding]`; `finding = { line, col, len, exact, code, msg, sev:'error'|'warn'|'info', source:'syntax'|'keys'|'mi'|'lng' }`.
  The page runs it 250 ms after the last change of an `sdl`, `lng` or `lua` buffer. `.lua`: intel/lua.js `luaCheck` (structure only: strings, long comments, brackets, function/if/do/repeat blocks). `.lng`: lnglint `lintBuffer` (source `lng`).
  Sources: lib/sdlx.read on the buffer (logic of tools/_retired/lsp/lsp.js lintText: drops UNREPLACED_PARAM for a single buffer; INCLUDE_MISSING and MACRO_UNDEFINED are kept only with a game, after the include was looked for in the mod folder, ictx.vfs and the game view, and never in .inc/.ext fragment files; without a game both are dropped), keylint.lintBuffer, milint/mi.js lintMi for `.mi`, lnglint if it can take a buffer. De-duplicated on line+code+msg, sorted by line, col, cut to 500 (+1 info CHECK_CAPPED), then located. Text over ictx.maxChars gives one info finding CHECK_SKIPPED_BIG and no checks. Never throws (a crash becomes one `CRASH` finding on line 1).
- `locate(f, lineText) -> { col, len, exact }`: token by code rule, else a quoted name in the message, else first non-space to end of line with `exact:false`.
- `kindOf(key|filename) -> 'sdl'|'lng'|'po'|'lua'|'log'|'text'`. `po` = `.po`/`.pot` (the GoH text files): intel/po.js `poCheck` (source `lng`; GHLOC-06 rules: no msgctxt or fuzzy = dropped, keys in lower case; GHLOC-08: same key twice in one file = the first wins; lenient reading as vanilla GoH .pot files need). Under GoH (`gameOf(ictx).kind === 'goh'`) a `.mi` goes to milint `lintMi` with `game:'goh'` (its GoH mission vocabulary, the same call milint makes under `--exe goh`); findings keep their severity.
- MoW:AS2 hover/words (game `mowas2` or exe `mowas_2` named): `keylint/vocab.mowas2.json` when it is there (as keylint `--exe mowas_2` picks), else `vocab.json`; engine field row and limits rows as AS64.
- GoH hover/words: `keylint/vocab.goh.json`; limit links from `intel/gohkeys.json` (`node tools/ide/intel/limkeys.js --goh`, rows), no as64 engine field row.
### tools/ide/intel/nav.js (part nav)
- `hover(doc, pos, ictx) -> null | { line, col, len, what:'key'|'value'|'path'|'entity'|'include'|'define'|'tag'|'lng', title, lead:{k,p}, rows:[{k:{k,p}|string, v:string}], links:[{text|k, link}] }`.
  `pos = {line, col}`. `lead.k` and row label keys are `ide.h.*` strings in tools/gui/ext/ide/lang/hover.js (4 languages), `p` fills `{slots}`. Values are data (names, types, paths) and stay as they are.
- `def(doc, pos, ictx) -> [{ link, label, line? }]` (0 = nothing, 1 = jump, more = pick). `link` is a link form below.
- `refs(doc, pos|{name}, ictx) -> { name, kind, hits:[{ link, where:'mine'|'othermod'|'vanilla', text }], truncated }`.
- `symbols(doc) -> [{ name, line, endLine, depth }]` (blocks to depth 2).
- `words(kind, ictx) -> [{ w, hint? }]` (autocomplete words for a file kind/extension, sorted, at most 4000).
- `wordAt(text, pos) -> { word, line, col, len, quoted } | null`.
### tools/ide/intel/fixes.js (part fixes)
- `fixes(doc, findings, ictx) -> [{ id, code, line, label:{k,p}, safe:bool, edits:[{ line, col, endCol, text }] }]` for line-local fixers only (include, spell, syntax, macro; repoint and asread fire only for findings passed in from a whole-mod run, so their codes are not in FIX_CODES). An edit may carry `dropEol:true`: delete the range and, the line being empty then, the line with its line end. `label.k` = `ide.f.*` in lang/fixes.js. `endCol` is exclusive; `col===endCol` inserts; an edit with `line` = N and `col` = 0 inserts a whole new line before line N.
- `warm(ictx) -> Promise<bool>` starts the background build of the define index (50 file reads per slice); `ready(ictx) -> bool`; until ready, macro fixes are absent. `FIX_CODES` = codes check() can produce that have a fixer.
- `apply(text, edits) -> text`. `multi(findings) -> [code]`: codes whose fix needs the patch-mod tool (lng, whole-file enc, stubmtl, quarantine).

### tools/ide/intel/cli.js (part check)
`run(argv) -> exit code`. `ide check|hover|def|refs|symbols|words|fixes <file> [--mod DIR] [--game DIR] [--line N] [--col N] [--json] [--pause]`. `check` prints `<file>:<line>:<col>: <CODE> <msg>` and `N findings`; exit 1 when there are errors. `--pause` waits for Enter (Notepad++ Run menu).
### tools/ide/npp/index.js (part npp)
- `status(o) -> { exe, version, settingsDir, running, portable, cloud, installed:{manifest|null}, problems:[code] }`
- `plan(o) -> { ok, refuse:[{code,msg}], targets:[{ path, action:'new'|'skip'|'merge'|'stage', why, diff? }], elevated:[{ from, to, cmd }] }`
- `install(o) -> plan + { backup, manifest }`; `uninstall(o) -> { removed:[], kept:[{path,why}] }`
- `open(o) -> { ok }`: `{ file, line, col, readOnly }` starts `notepad++.exe -n<line> -c<col> [-ro] <file>` (shell:false, detached).
- `o = { settingsDir?, exe?, theme? (path to the user's GEM2.xml), launcher? ({file, args} that runs `ide`), functionList? (true = also install the function list; off by default), extSkip? (extensions to leave out of the language) }. No force: a refusal always stops. `status.running` is true|false|'unknown' (unknown refuses with RUN_UNKNOWN); a bad manifest refuses with BAD_MANIFEST; a target that replaces a user file has `replace:true`; plan adds `exts` and `notes`; a failed install returns `{ok:false, partial:true, error, written, backup, manifest}``. Tests pass a fake `settingsDir` and `exe`.
- `tools/ide/npp/cli.js run(argv)`: `ide npp status|plan|install|uninstall [--theme f] [--settings d]`, `ide send <file> [line] [col]`, `ide vanilla <file>`.
  `send` reads `%LOCALAPPDATA%\ARSENAL\gui.json` `{port,pid,token}`, POSTs `/api/x/ide/inbox` `{token, file, line, col}`; if no GUI answers it prints how to start one, exit 3.

A gap inside an unquoted child of a quoted block (a block setting) moves after its closer. A `(mod)` frame inside a reaction does not hide the reaction, and a top-level `(mod ...)` is transparent for the fragment-file rule; in a fragment file a gap inside a top-level setting moves after it. ## Routes (part routes; JSON in, JSON out; errors = throw Error with `.status`)
Client still uses the existing `/api/x/files/{tree,which,open,save,copy,undo,restore,search}` for file work (shapes: tools/gui/ext/files/lib.js).
A `rel` of the form `<pak>::<entry>` is a text file inside one of the mod's own paks: `open` gives it editable (`inPak` = the pak), `save` writes the pak again with that entry replaced (tools/lib/pakpatch.js: the other entries are copied as the packed bytes they are, with name, time and method kept, so a pak of any size works; temp file then rename), and the restore point holds the entry's old bytes. Game paks are never written.
`ref` = one of `{mod, rel}` (file in the mod) | `{mod, key, idx}` (a layer of the game index) | `{mod, path}` (absolute, read-only).
- `GET  /api/x/ide/asset?f=cm.js|cm.css|ide.js|ide.css` -> `{ __raw: text, type }` (gui.js sends it raw). cm.* = tools/gui/vendor/cm5/cm5.bundle.json; ide.js / ide.css = tools/gui/ext/ide/cm/index.js `{js, css}`.
- `POST /api/x/ide/lint` `{...ref, text}` -> `{ findings, fixes, multi, ms }`
- `POST /api/x/ide/hover` `{...ref, text?, line, col}` -> `{ hover }` (hover, def, refs, symbols: without `text` the route reads the file from disk, so a saved doc sends only its ref; lint always needs `text`)
- `POST /api/x/ide/def` `{...ref, text?, line, col}` -> `{ targets }`
- `POST /api/x/ide/refs` `{...ref, text?, line, col}` or `{mod, name}` -> refs shape
- `POST /api/x/ide/symbols` `{...ref, text?}` -> `{ symbols }`
- `GET  /api/x/ide/words?mod=&kind=` -> `{ words }`
- `GET  /api/x/ide/vdir?mod=&dir=[&off=&lim=&ver=]` -> `{ dir, dirs:[name], files:[{ name, key, where:'mine'|'othermod'|'vanilla', layer, size }], truncated:false, total, off, next, ver?, notes? }` (merged game view, lazy per folder; dir '' = `resource`). With `&vanilla=1`: only the game's own files, each as the game's copy even where a mod overrides it; files carry `idx` (layer of the game index), opened with `{ mod, key, idx }`. (v2) No file maximum: `truncated` is always false (kept for older callers).
- (v2) Paging, the same for vdir, tree and vfind: no listing stops at a file count. Without `lim` the whole list comes in one answer. With `lim` (1..50000) one page: `off` (where it starts), `next` (where the next page starts, null on the last), `total` (rows of the whole list; for tree null while the walk still runs), `ver` (stamp of the list). The list is kept a short while (8 lists, 2 min) under its stamp; a page asked with `ver` comes from that same list, so the order holds. A stamp that is gone gives a list read again with a new `ver`: the caller starts again from 0. A vdir page holds folders first, then files (one row index over both). 400 for a bad `off` or `lim`.
- (v2) `GET  /api/x/ide/tree?mod=[&off=&lim=&ver=]` -> `{ mod, files:[{ rel, size, state, key }], total, off, next, ver, done, unread, partial?, error?, truncated:false, notes, game, undo }`: the files/tree answer with no file maximum. Same rows and order as files/lib tree; the walk runs in slices and a page is answered as soon as its rows are there. `unread` = folders or paks that could not be read. The explorer falls back to `/api/x/files/tree` when this route answers 403, 404 or 501 (an older server, a phone).
