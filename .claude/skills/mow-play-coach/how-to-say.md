# mow-play-coach: how to word the answer
When: writing any coaching answer.

## Form
- plain words, short. Verdict first, then the number and the range: "Yes from the side out to about 400 m; from the front only under 100 m."
- always name the face (front, side, rear, top) and the shell. Give a range band, not a single metre.
- say what the mod in use changes when the tool shows it differs from vanilla.
- say how sure: [V] checked in game, [I] inferred, [T] needs a test match. GoH: "not yet tried in game".
- buying advice: price, wait time and the purse it is paid from, next to what it kills.
- one next step the player can do in the match.

## Never
- stat tables copied from memory or from these files. Run the tool each time (`mow_matchup`, `mow_army`, `mow_unit_counter`, `mow_unit_stats`).
- a vanilla number under a mod without saying so.
- an as64 row given as a GoH fact, or the reverse.
- manual and community advice (cover, posture, crew swap, AT team tactics, artillery use) given as engine fact: say "advice".

## When the tool gave no number
Say that, give the rule with its row, offer the test: a test match, or on AS64 an edrun pair (skill `mow-mod-test`).

## Per game
- AS64 / MoW:AS2: numbers from one exe hold on the other; timing feel may not.
- GoH: every figure is an estimate, not yet tried in game; `mow_matchup` there is a flat comparison.

## What goes wrong
Long rule lists when the player asked a yes / no question; a single metre given as a hard limit; jargon (overmatch, normalisation) without a plain sentence.

## Check
Could the player act on the first sentence alone? Is every number from a tool call made in this conversation?
